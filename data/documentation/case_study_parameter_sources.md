# Evidence Rules for Economic Model Parameters

## 1. Purpose

This document defines how numerical inputs will be selected for the diabetic retinopathy economic model.

## 2. Preferred evidence hierarchy

Where available, use the following order:

1. Relevant NHS England or UK government published data.
2. NICE or other recognised UK health technology assessment evidence.
3. Peer-reviewed UK clinical and economic studies.
4. Peer-reviewed studies from comparable healthcare systems.
5. International studies with clearly documented methods.
6. Explicitly labelled illustrative assumptions, used only where necessary for scenario exploration.

## 3. Cost inputs

All costs used in an NHS-focused model should be:

- Reported in GBP.
- Assigned a price year.
- Linked to a traceable source.
- Defined as direct, indirect or implementation costs.
- Adjusted for inflation where appropriate.
- Clearly distinguished from non-cash capacity changes.

International costs must not be entered as NHS costs without a documented conversion and adaptation method.

## 4. Clinical inputs

Sensitivity, specificity and other clinical parameters should be taken from relevant validation studies or systematic reviews.

The population, disease definition, reference standard and screening pathway must be recorded.

Diagnostic accuracy from one population should not automatically be assumed to apply to another.

## 5. Workforce inputs

Staff time, staff grades, salaries and activity assumptions must be supported by published data or transparent calculations.

A reduction in staff time is not automatically a financial saving.

## 6. Missing data

Where a parameter cannot be identified:

- Leave the base-case value blank.
- Record the evidence gap.
- Explain why the parameter is required.
- Identify whether a scenario analysis could be appropriate.

Do not invent a numerical value.

## 7. Illustrative assumptions

Any illustrative assumption must be clearly labelled.

It must not be described as observed NHS data or a measured clinical result.

The effect of alternative assumptions should be examined through sensitivity or scenario analysis.

## 8. Documentation

Every populated model parameter must have:

- A parameter identifier.
- A numerical value.
- A unit.
- A source identifier.
- A page, table, figure or section reference.
- A price year where relevant.
- A short explanation of any adjustment.
- A note on uncertainty and transferability.

## 9. Reproducibility

The parameter register, source register, extraction file and analysis code should be sufficient for another reader to understand how the model inputs were selected and how the results were produced.
